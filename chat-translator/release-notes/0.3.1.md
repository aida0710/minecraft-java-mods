macOS 向けの修正です。Intel の Mac で GPU を使うと説明していた誤りを直しました。/ Fixes for macOS, including a wrong statement that Intel Macs use the GPU.

## 日本語

### 使うローダーの jar を 1 つ選ぶ

対応: Minecraft 26.3 / Java 25

| ローダー | jar | 必要なもの |
| --- | --- | --- |
| Forge 66 以降 | `chattranslator-forge-0.3.1.jar` | |
| NeoForge 26.3.0 以降 | `chattranslator-neoforge-0.3.1.jar` | |
| Fabric Loader 0.19.5 以降 | `chattranslator-fabric-0.3.1.jar` | Fabric API |

### 直したこと

- **Intel の Mac**: 0.3.0 の説明と設定画面には Metal を使えるように書いていましたが、Intel 用の llama.cpp は Metal に対応していません。説明を直し、設定画面に GPU の項目を出さないようにしました。Intel の Mac では CPU で動きます
- **macOS 13**: MLX は macOS 14 以降にしか対応していないので、macOS 13 では選択リストに出さないようにしました
- **Gatekeeper**: ダウンロードした llama-server・uv・Python 環境から、macOS の隔離の印を外すようにしました。これらは公証されていないので、印が付いていると起動を止められるおそれがあります

### 0.3.0 から更新するとき

- Intel の Mac では、更新後にもう一度「インストール」を押してください。llama.cpp をダウンロードし直します (約 12MB)。モデルはダウンロードし直しません
- 0.3.0 で内蔵 LLM を起動できなかった Mac では、設定画面の「削除」を押してからインストールし直してください

### 動作を確かめていないもの

- Mac の実機 (macOS の確認は GitHub Actions の仮想環境で行いました。Apple silicon の macOS 14・15・26、Intel の macOS 15、Rosetta で動かす x64 の Java です)
- Intel の Mac のゲームの中での動作 (Intel の仮想環境では、ゲーム本体が画面を作る前に異常終了しました。原因は分かっていません。内蔵 LLM のインストールと翻訳はゲームの外のテストで確かめました)
- macOS 13
- RTX 50 シリーズでの NVFP4 と、RTX 40 シリーズ以降での FP8 本来の動き (RTX 3080 Ti では、FP8 は重みだけ FP8 で動き、NVFP4 は起動に失敗しました)
- WSL2 の中で GPU を使って vLLM を動かすこと
- TranslateGemma の FP8・NVFP4 の翻訳

## English

### Pick the jar for your loader

Requires Minecraft 26.3 and Java 25.

| Loader | Jar | Also needs |
| --- | --- | --- |
| Forge 66 or later | `chattranslator-forge-0.3.1.jar` | |
| NeoForge 26.3.0 or later | `chattranslator-neoforge-0.3.1.jar` | |
| Fabric Loader 0.19.5 or later | `chattranslator-fabric-0.3.1.jar` | Fabric API |

### What's fixed

- **Intel Macs**: The 0.3.0 notes and settings screen said Metal was available, but llama.cpp for Intel does not support Metal. The notes are corrected and the settings screen no longer shows the GPU option. Intel Macs run on the CPU
- **macOS 13**: MLX only supports macOS 14 or later, so it is no longer listed on macOS 13
- **Gatekeeper**: The mod now removes the macOS quarantine mark from the downloaded llama-server, uv and Python environment. They are not notarized, so Gatekeeper may block them if the mark is present

### Updating from 0.3.0

- On Intel Macs, press Install again after updating. This downloads llama.cpp again (about 12 MB), but not the model
- If the built-in LLM failed to start on your Mac with 0.3.0, press Delete in the settings screen and install it again

### Not verified

- Real Macs (macOS was checked in GitHub Actions virtual machines: macOS 14, 15 and 26 on Apple silicon, macOS 15 on Intel, and x64 Java under Rosetta)
- The game itself on Intel Macs (in the Intel virtual machine, the game aborted before opening its window, for an unknown reason. Installing and translating with the built-in LLM were checked in tests outside the game)
- macOS 13
- NVFP4 on RTX 50 series GPUs, and FP8 at full speed on RTX 40 series or later (on an RTX 3080 Ti, FP8 ran with FP8 weights only, and NVFP4 failed to start)
- Running vLLM on a GPU inside WSL2
- Translating with the FP8 and NVFP4 versions of TranslateGemma
